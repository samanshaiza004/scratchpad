## Million-line semantic-plan worker

The opt-in bridge diagnostic ran in three independent processes against the
current pinned Caliber and Alicorn. Each process built plans for a generated
18,981,000-byte prose fixture containing one million newline-terminated rows,
1,000 paragraphs, and 1,000,001 buffer lines including the trailing empty
line. Each run collected 20 successful worker requests and one cancellation.

| Process | Request→ready p50/p95 | Worker build p50/p95 | Cancel ack / worker exit | Go heap allocated baseline→peak | Go heap in-use baseline→peak |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 26.880 / 30.855 ms | 26.680 / 30.611 ms | 0.049 / 0.103 ms | 37.61→95.22 MB | 38.84→96.33 MB |
| 2 | 26.667 / 30.625 ms | 26.513 / 30.443 ms | 0.088 / 0.131 ms | 55.72→95.19 MB | 56.88→96.26 MB |
| 3 | 27.411 / 28.973 ms | 27.243 / 28.758 ms | 0.073 / 0.080 ms | 55.71→87.54 MB | 56.86→88.59 MB |

For process 3, a macOS `getrusage(RUSAGE_CHILDREN)` wrapper measured **121.29
MB peak RSS** for the diagnostic test process. This is process RSS for the
isolated Go bridge diagnostic, not the Scratchpad GUI's working-set/high-water
memory during application use. Go heap values are shown separately because
they are not process RSS.

The repeated worker measurements are consistent: construction completes in
roughly 27–31 ms at p50/p95, and the observed cancellation exits within 0.08–
0.13 ms. They establish worker behavior for this synthetic fixture; they do not
measure native input-to-visible latency, first accepted typing/scrolling, AX
serialization, or full application memory.

Automated regression tests also cover snapshot isolation, editing while a
worker is deliberately blocked, cancellation and request supersession, and
stale document/revision rejection. Those are part of the full test pass above.

## Remaining #17 acceptance

- **macOS native responsiveness:** current-candidate physical measurements of
  time to first accepted typing/scrolling and UI-to-visible latency remain
  unrecorded. The earlier 6a72339 GUI timings are not substitutes.
- **macOS interaction:** rerun pending-plan typing, scrolling, paste/IME,
  cancellation, source switching/closing, and multi-window checks against the
  current candidate in a real desktop session.
- **macOS recovery/package:** current-candidate conflict handling, recovery,
  and signed app/relocated-package launch, quit, and relaunch remain unverified.
- **Windows quantitative acceptance:** the current report has worker timings
  and Go heap measurements, but native UI-to-visible/first-input latency and
  process working-set peak are still missing.

The worker implementation and its automated correctness checks are established
on this candidate. Issue #17 should remain open until the native and package
acceptance above is recorded; those checks require an interactive desktop and,
for Windows, a Windows host.
